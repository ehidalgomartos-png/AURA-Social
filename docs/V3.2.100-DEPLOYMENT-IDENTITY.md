# RedLibertad V3.2.100 — Identidad verificable del despliegue

**Base:** V3.2.99 (`c20a4cf89bdc44e5b5123f0a2e4f36107a95cfd8`).

## Problema
`server.js` seguía mostrando una versión fija `3.2.77` en `/api/health`, pese al progreso de las versiones. El dato no permitía distinguir un despliegue antiguo de uno nuevo.

## Solución
- La versión de la aplicación sale de un solo origen: `package.json`, ahora `3.2.100`.
- `/api/health` y `/api/public-config` publican `deployedCommit`: el SHA hexadecimal de 40 caracteres suministrado por Coolify en la variable de entorno predefinida `SOURCE_COMMIT`.
- Si `SOURCE_COMMIT` no está presente o es inválido, se publica `deployedCommit:null`: **no inventar un SHA** ni asumir que el servidor tiene el último `main`.
- No se exponen secrets, bases de datos, tokens ni identificadores internos de Coolify.
- Hay pruebas específicas en `npm run test:deployment-identity`, integradas en GitHub Actions.

## Comprobación en Coolify después de fusionar
1. Comprobar que la aplicación ha desplegado el SHA fusionado, sin modificar variables existentes.
2. Abrir `https://redlibertad.com/api/health` y revisar `version` y `deployedCommit`.
3. Comparar `deployedCommit` con el commit más reciente de `main` en GitHub.
4. Si `deployedCommit` es `null`, verificar primero en Coolify la lista de despliegues y la variable predefinida `SOURCE_COMMIT`. No declarar el despliegue validado solo por `version`.
5. Confirmar que el sitio principal, Marketplace y piloto de MundoTaza siguen operativos.

## Riesgos y límites
Este cambio es **solo observabilidad**. No habilita Stripe LIVE, planes comerciales, precios definitivos, contratos, permisos pagados, cobros de producto ni migraciones. Las compras continúan en la tienda externa y MundoTaza sigue en el piloto gratuito.

La confirmación del entorno de producción **no** sustituye la validación de extremo a extremo con Stripe TEST ni las revisiones legales y fiscales antes del lanzamiento.
