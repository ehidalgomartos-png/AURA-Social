# RedLibertad V3.2.100 — Verificar el commit desplegado en Coolify

Base estable: V3.2.99, commit c20a4cf89bdc44e5b5123f0a2e4f36107a95cfd8.

## Nuevo identificador de despliegue
- /api/health y /api/public-config incorporan `deployedCommit`.
- El valor proviene exclusivamente de `SOURCE_COMMIT`, variable predefinida de Coolify disponible en tiempo de ejecución.
- Solo se publica un SHA hexadecimal válido de 40 caracteres. Sin dato confiable se devuelve `null`; no se infiere que el despliegue esté actualizado.
- Se conserva por compatibilidad el identificador histórico `version: 3.2.77` usado por pruebas y herramientas antiguas; **no se debe utilizar ese campo para confirmar el despliegue**. El identificador correcto es `deployedCommit`.
- Pruebas nuevas: `npm run test:deployment-identity`, integradas en el CI completo, sin tocar suites históricas.

## Validación operativa
1. En Coolify, comprobar el último despliegue y su commit, con estado Running.
2. Abrir https://redlibertad.com/api/health y comparar `deployedCommit` con el SHA completo de `main` en GitHub.
3. Si el valor es nulo, comprobar en Coolify la disponibilidad de la variable predefinida `SOURCE_COMMIT`. No declarar validado el despliegue en ese caso.
4. Verificar que el Marketplace, WooCommerce y el piloto gratuito de MundoTaza siguen funcionando.

## Restricciones
El cambio es exclusivamente de observabilidad. No activa Stripe LIVE, pagos, precios finales, permisos pagados, contratos, consentimiento ni migraciones. Los productos continúan cobrándose en la web del vendedor.
