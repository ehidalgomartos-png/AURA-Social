# V3.4.0 — Aceptación de crecimiento consolidado

La versión consolida lo existente; **no crea usuarios, conversaciones, publicaciones, campañas, notificaciones ni actividad artificial**.

## Cambios de esta versión

- El campo `releaseMilestone` de `/api/health` y `/api/public-config` anuncia `3.4.0`. El campo técnico de compatibilidad `version` sigue en `3.2.77`; no se cambia el contrato de integraciones existentes.
- Nueva generación de la caché pública PWA (`redlibertad-v3400-*`) para renovar shells y archivos públicos. Continúa excluyendo API, ficheros multimedia, admin y páginas con contenido sensible.
- Prueba de regresión consolidada que exige control de despliegue por SHA, PostgreSQL 18, activación real, publicaciones, métricas D1/D7, SEO, PWA, privacidad y versiones anteriores.

## Criterios automáticos para cerrar el PR

1. Crear rama sobre último `main` estable; comprobar SHA base.
2. Completar todas las pruebas JavaScript de GitHub Actions, incluidas las de V3.3.40 y D1/D7.
3. Completar el trabajo de integración PostgreSQL 18.
4. Fusionar PR solo si ambas comprobaciones son correctas, confirmar nuevo SHA en `main`.
5. Comprobar Actions posteriores al merge y verificador público de `/api/health`, `/api/public-config` y `/api/ready` con el SHA **exacto** del merge. Un green de CI no sustituye producción.

## Evidencia que sigue pendiente de validación manual

- **Móvil:** pruebas de publicación, comentarios, chat, instalación/actualización PWA, navegación, teclado y badges en Android e iOS reales.
- **Escritorio:** Inicio, Explorar, perfiles, mensajes, Marketplace y visualización de medios en resoluciones habituales, con usuario real de pruebas.
- **Centro de crecimiento:** comprobar en el panel administrador los datos reales y tamaños de cohorte para D1/D7. Las métricas ya existen, pero no se inventan cantidades ni se infiere retención de muestras inmaduras.
- **Coolify:** revisar logs, capacidad del VPS y configuración del volumen local de multimedia.
- **Backups y restauración:** comprobar backups periódicos y recuperación aislada de PostgreSQL 18 y medios, siguiendo `docs/V3.3.40-AUDITORIA-Y-RECUPERACION.md`. Sin ello, la recuperación ante pérdida de datos no está demostrada.
- **Search Console:** comprobar indexación real de páginas públicas, canónicos y errores de cobertura; un sitemap correcto no demuestra indexación.
- **Privacidad operativa:** probar bloqueo, moderación, contenidos sensibles, enlaces compartidos y consentimiento con cuentas propias. No compartir mensajes ni adjuntos de terceros para hacer pruebas.

**Estado:** la aceptación de los apartados anteriores está **pendiente de validación manual**. No se debe afirmar que el lanzamiento ha superado pruebas físicas de móvil/escritorio ni restauraciones reales basándose únicamente en GitHub Actions.

## Recuperación

Si el nuevo commit no pasa `/api/ready` o falla la comprobación de SHA en producción, detener el avance y revisar el despliegue en Coolify. Volver al artefacto anterior comprobado antes de tocar datos persistentes. La reversión de código no debe restaurar ni borrar automáticamente PostgreSQL o multimedia.
