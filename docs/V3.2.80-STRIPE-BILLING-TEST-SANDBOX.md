# RedLibertad V3.2.80 — Laboratorio Stripe Billing TEST

**Base estable:** \`main\` V3.2.79 \`f5af39cac9aef16379336c303ea95a9a2d8a2e7f\`.
**Rama:** \`redlibertad-v3.2.80-stripe-billing-test-sandbox\`. **PR sin fusionar hasta autorización expresa.**

## Qué hace
- Nuevo laboratorio privado de administradores: \`/marketplace/suscripciones/laboratorio\`, accesible desde la gestión de suscripciones. No hay CTA pública para contratar.
- \`GET /api/marketplace/subscriptions/admin/stripe-test/status\` — configuración disponible, estado de prueba, intentos y eventos propios.
- \`POST /api/marketplace/subscriptions/admin/stripe-test/checkout\` — **solo admin**, requiere Origin de mismo host, JSON con uno de los códigos de plan permitidos, toma la tarifa **solo del servidor** y crea Stripe Checkout en \`mode=subscription\`. No acepta IDs de vendedor, importes, precios ni URL de pago del cliente.
- \`POST /api/marketplace/subscriptions/admin/stripe-test/portal\` — **solo admin**, abre Stripe Customer Portal de prueba para el cliente Stripe TEST asociado a ese usuario; allí se puede probar cancelación y actualización de pago simulado.
- \`POST /api/marketplace/stripe-test/webhook\` — endpoint no autenticado por sesión, pero **autenticado por firma Stripe del cuerpo crudo** y marca temporal (tolerancia 5 minutos). El webhook se monta antes de \`express.json\`, requiere \`livemode=false\`.
- Tablas completamente aisladas: \`marketplace_stripe_test_checkouts\`, \`marketplace_stripe_test_subscriptions\`, \`marketplace_stripe_test_events\`. Eventos idempotentes por \`event_id\`. Solo se procesan suscripciones TEST con metadatos \`sandbox=redlibertad_v3280\`, propietario y precio de test coincidentes.
- Checkout/Portal únicamente a hosts oficiales Stripe y HTTPS; peticiones salientes únicamente a API fija \`https://api.stripe.com\` con clave \`sk_test_\` válida. Sin Stripe Connect, transferencias ni acceso a checkout de productos.

## Estado inicial seguro
**Por defecto no existe ningún acceso a Stripe, porque todas las opciones están desactivadas.** No configurar variables hasta autorizar las pruebas. No publicar ninguna clave en GitHub ni en este chat. No pedir números de tarjeta reales.

En Coolify, para probar después del PR y del despliegue, el administrador deberá crear:
- \`STRIPE_TEST_BILLING_ENABLED=true\` (por defecto ausente/false).
- \`STRIPE_TEST_SECRET_KEY=sk_test_...\` (nunca \`sk_live_\`).
- \`STRIPE_TEST_WEBHOOK_SECRET=whsec_...\` (del endpoint de test).
- \`STRIPE_TEST_PRICE_PROFESSIONAL=price_...\` y \`STRIPE_TEST_PRICE_PROFESSIONAL_PLUS=price_...\` (precios recurrentes reales **en entorno TEST**, euros, importes de laboratorio).
- \`APP_ORIGIN=https://redlibertad.com\` (si no está ya configurado). No sobrescribir claves de WooCommerce ni variables existentes.

Endpoint Stripe TEST para configurar el webhook en el dashboard: \`https://redlibertad.com/api/marketplace/stripe-test/webhook\`.
Eventos recomendados: \`checkout.session.completed\`, \`checkout.session.expired\`, \`customer.subscription.created\`, \`customer.subscription.updated\`, \`customer.subscription.deleted\`, \`invoice.paid\`, \`invoice.payment_failed\`.
Los eventos de factura se registran como recibidos pero **no** crean autorizaciones o cambios en cuentas reales. El retorno desde Checkout **no acredita** pago: el estado depende de eventos verificados.

## Prohibiciones explícitas
- No activar \`STRIPE_SECRET_KEY\` normal, Stripe live, precios reales, pagos en producción, facturación real ni cobros para vendedores.
- No insertar ni modificar \`marketplace_seller_subscriptions\`, \`marketplace_subscription_audit\`, \`marketplace_professional_stores\`, \`marketplace_external_products\`, \`marketplace_listings\` ni datos personales de MundoTaza.
- No conectar el laboratorio a los permisos del Marketplace, sincronización WooCommerce, Google Merchant, productos externos o mensajes.
- No migrar ni aplicar vencimiento o plan a MundoTaza. MundoTaza conserva piloto ilimitado.
- El modo test puede registrar métodos de pago de prueba y producir facturas de prueba **en Stripe TEST exclusivamente**; no se presenta como pago efectivo ni como cuota vigente de RedLibertad.

4. Con variables test (solo después de autorizar): admin crea Checkout de prueba, usa tarjeta de **test**, recibe webhook firmado, ve evento y accede a Customer Portal; renovación/cancelación únicamente TEST.
