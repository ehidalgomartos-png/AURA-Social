# RedLibertad V3.2.120 — Auditoría SEO interna y preparación para indexación

## Motivo

La V3.2.119 fue confirmada como desplegada en Coolify. Se intentó comprobar desde fuera el sitemap, la landing y robots.txt, pero la herramienta externa no consiguió conectarse con redlibertad.com. Esto **no prueba que Google o el público tengan problemas de acceso**. Las rutas y sitemaps sí existen en el código validado.

Antes de crear más páginas SEO, la prioridad pasa a ser identificar problemas concretos de contenido y calidad en el inventario ya publicado.

## Panel privado

- Pantalla: `/marketplace/seo/auditoria` (**solo administrador**).
- API: `/api/admin/marketplace/seo/auditoria` (**solo administrador**).
- Ambos extremos exigen `requireAdmin`, establecen `Cache-Control: private,no-store` y `X-Robots-Tag: noindex,nofollow`. La página incluye además `meta robots noindex,nofollow`.
- El panel es mobile-first y de solo lectura; se puede actualizar manualmente desde el botón «Actualizar diagnóstico».
- Solo utiliza consultas de lectura y no modifica datos, páginas públicas, sitemaps, WooCommerce ni compras.

## Datos y límites del diagnóstico

Los recuentos globales proceden **únicamente de anuncios activos/publicados de vendedores activos y públicamente descubribles**, con la misma regla que usa el sitemap:

`l.status='active' AND l.moderation_status='published' AND u.status='active' AND u.discoverable=true`.

El resumen incluye productos, servicios, inmuebles, títulos muy breves (menos de 18 caracteres), descripciones breves (menos de 70), galerías vacías y productos sin estado nuevo/usado indicado. Estos límites son **criterios editoriales de revisión**, no estándares oficiales ni penalizaciones automáticas de Google.

Se analizan individualmente como máximo los **100 anuncios públicos actualizados más recientemente** para localizar referencias de imágenes con formato no permitido, imágenes repetidas y fichas con poco contenido. La lista de ejemplos no es un censo exhaustivo si hay más de 100 anuncios.

La auditoría también consulta los recuentos reales de las diez colecciones SEO del Marketplace y aplica el mismo umbral ya existente para mostrar si están aptas para aparecer en el sitemap de categorías. No genera nuevas URLs ni fuerza indexación.

**Esta auditoría NO accede a los datos de Google Search Console ni sabe qué fichas están realmente indexadas.** Para conocer impresiones, clics, estado de cobertura y canónica seleccionada por Google hay que utilizar Search Console. El panel lleva un enlace a ese servicio y a los sitemaps.

## Seguridad

- No devuelve emails, identificadores de cuentas, teléfonos, credenciales, metadatos de Stripe ni perfiles privados. Los ejemplos solo contienen ID, título, categoría, tipo, URL pública y códigos de aviso.
- JavaScript del panel usa `textContent` y elementos DOM seguros, sin `innerHTML` para el contenido que provenga de anunciantes.
- Sin efectos de escritura ni herramientas de publicación automáticas.
- El piloto gratuito MundoTaza no se modifica. Se preservan WooCommerce, fotos, productos y compras exclusivamente en la web del vendedor.
- Sin activar Stripe LIVE, cobros, facturación, cambios fiscales/legales, permisos profesionales ni precios publicados.

## Pruebas de regresión

- `npm run test:marketplace-seo-audit`: aislamiento `requireAdmin`, noindex/no-store, medidas verdaderas, auditoría sin secretos, muestra limitada y representación segura en móvil.
- GitHub Actions PostgreSQL 18: datos de prueba en tablas temporales con fichas públicas, ocultas, pausadas y de vendedores privados o suspendidos; verifica que solo las públicas aparecen en resultados y recuentos.
- Se mantienen obligatorias todas las pruebas históricas de SEO, Marketplace, importador CSV, Stripe TEST y seguridad.

## Validación después del despliegue

1. Abrir `https://redlibertad.com/marketplace/seo/auditoria` con una sesión de administrador; comprobar que el panel muestra recuentos y categorías.
2. Sin sesión, comprobar que devuelve **401**; con cuenta normal, **403**. La API debe tener la misma protección.
3. Comprobar que la página no figura en los sitemaps y responde con `noindex,nofollow` y `no-store`.
4. Confirmar que el resumen no incluye anuncios ocultos o vendedores privados y que las fichas señaladas corresponden a URLs públicas.
5. Revisar el sitemap público `/sitemap-marketplace-productos-1.xml` para verificar las fotografías múltiples de la V3.2.119.
6. Comparar el panel con Search Console para elegir mejoras reales de indexación: no atribuir a Google los avisos internos ni garantizar posicionamiento.

No fusionar si las pruebas fallan o si el diagnóstico parece exponer datos privados.
