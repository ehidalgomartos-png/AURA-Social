# RedLibertad V3.2.96 — Vinculación comprobada de Stripe TEST

Base: V3.2.95, commit `8db6e717a5c09a9f0a35c502a4a845624390b2f3`.

## Corrección
- Eventos `customer.subscription.*` sólo pueden actualizar la tabla de suscripciones de prueba si existe un Checkout creado por RedLibertad, completado y con la **misma combinación exacta** de vendedor, plan, `customer_id` y `subscription_id`.
- Una mera coincidencia en metadatos `seller_id` y `plan_code` ya no basta.
- Si existe un Checkout TEST pendiente, se devuelve error reintentable (503) y se revierte la transacción, incluso la inserción de `event_id`. Esto permite que Stripe entregue después el evento, cuando ya se haya registrado la finalización. No se inventan estados ni se confía en redirecciones del navegador.
- Eventos que no tienen asociación posible se auditan como no aplicados sin crear suscripciones.
- Añadidas pruebas de vinculación exacta, intento de asociar otros IDs, ausencia de Checkout, reintento antes de completar y aislamiento del Marketplace real.

## Precauciones
- Stripe normalmente reintenta entregas que reciben respuesta HTTP 5xx, pero no se garantiza un reintento ilimitado. Si un evento expira antes de que se complete Checkout, necesitará inspección manual de eventos Stripe TEST; **no** se concede ningún permiso automáticamente.
- No hay migración ni cambios de variables.
- Exclusivamente tablas `marketplace_stripe_test_*`, sin habilitar permisos reales o cobrar.
- MundoTaza mantiene el piloto gratuito y la compra externa por WooCommerce.
