# RedLibertad V3.2.98 — Integridad del plan Stripe TEST

**Base:** V3.2.97 (`eb6b089088d4943dbcdb831a8c7640ea418efe0c`).

## Cambios de seguridad imprescindibles
- Un registro de suscripción Stripe TEST debe contener **un único concepto de precio** y **una unidad** si Stripe proporciona la cantidad. No se admiten suscripciones con varios conceptos o con más páginas de conceptos (`has_more=true`).
- El único precio debe corresponder al identificador configurado para ese plan de laboratorio. Se rechazan precios marcados explícitamente como `livemode=true`.
- La conciliación manual administrativa verifica la existencia de un Checkout local TEST completado con identidad exacta **antes de consultar la API de Stripe**. Las asociaciones no verificadas devuelven 409 sin efectuar peticiones remotas ni cambios de estado.
- Se mantiene el rechazo de eventos LIVE, la verificación de firma, la idempotencia, la reversión de eventos prematuros y la protección del piloto.

## Cobertura de pruebas
`npm run test:marketplace-stripe-plan-integrity` comprueba los casos de una unidad, múltiples precios, paginación, cantidad inválida, precio LIVE y conciliaciones sin vínculo o con discrepancia. También se ejecutan todas las regresiones previas en GitHub Actions.

## Límites
La versión no añade variables, migraciones, opciones de pago, planes vendibles o condiciones definitivas. Solo opera sobre el laboratorio TEST. No modifica estados comerciales ni suscripciones reales, productos, tiendas, importación WooCommerce, enlaces de compra o el piloto gratuito de MundoTaza.

## Validación operativa
Tras fusionar, verificar en Coolify el SHA desplegado. La integridad técnica del laboratorio no sustituye pruebas de extremo a extremo contra Stripe TEST con credenciales ya configuradas, ni las revisiones fiscales, legales y comerciales antes de autorizar Stripe LIVE.
