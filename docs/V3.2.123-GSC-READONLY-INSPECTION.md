# RedLibertad V3.2.123 — Google Search Console real, manual and read-only

## Qué cambia

La auditoría privada `/marketplace/seo/auditoria` permite consultar, **solo tras una pulsación expresa del administrador**, la respuesta real del API oficial de **URL Inspection** de Google Search Console para **una ficha pública** de RedLibertad.

Los sitemaps, productos, fotos y categorías existentes no cambian. La auditoría editorial no se convierte mágicamente en un informe de Google: las nuevas respuestas reales solo aparecen cuando se conecta una cuenta autorizada y Google responde a la consulta.

El endpoint de Google que se utiliza es:

- `POST https://searchconsole.googleapis.com/v1/urlInspection/index:inspect` — consulta la **versión que Google conserva en el índice**, no la página publicada en vivo.
- La autenticación se obtiene únicamente a través de `POST https://oauth2.googleapis.com/token`, con OAuth 2.0 JWT de cuenta de servicio RS256 de corta validez, audiencia fija, y **scope exclusivo** `https://www.googleapis.com/auth/webmasters.readonly`.
- **No se utiliza** `indexing.googleapis.com` ni se solicitan rastreos o indexaciones. Google restringe la Indexing API a determinados empleos y retransmisiones, no a fichas ordinarias de Marketplace.

Documentación oficial: https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect y https://developers.google.com/webmaster-tools/limits

## Activación opcional en Coolify — NO entregar claves en ChatGPT

**No hay conexión activa por defecto**. El panel permanece deshabilitado hasta que el propietario complete estas acciones fuera del chat:

1. En Google Search Console, localizar la propiedad existente de RedLibertad y **copiar su identificador exacto**. Se aceptan únicamente `sc-domain:redlibertad.com` o `https://redlibertad.com/`, según cuál sea la propiedad realmente verificada.
2. En Google Cloud Console, preparar un proyecto que tenga habilitada **Search Console API**, crear una **cuenta de servicio** para consultas de lectura y obtener su clave privada en el formato JSON de credenciales.
3. En Search Console, en **Ajustes → Usuarios y permisos**, añadir el **correo de la cuenta de servicio** a la propiedad correcta con acceso suficiente para consultar URL Inspection. Si faltan permisos, Google responderá que el acceso está denegado; la aplicación no cambiará derechos automáticamente.
4. Guardar **solo en las variables de entorno protegidas de Coolify** (no en el repositorio, páginas web, campos de chat ni capturas):
   - `GSC_READONLY_ENABLED=true`
   - `GSC_SITE_URL=sc-domain:redlibertad.com` (o la propiedad de prefijo verificada `https://redlibertad.com/`)
   - `GSC_SERVICE_ACCOUNT_EMAIL=<client_email de la cuenta de servicio>`
   - `GSC_SERVICE_ACCOUNT_PRIVATE_KEY=<private_key del JSON de la cuenta de servicio>`
5. La clave puede almacenarse como PEM con saltos de línea o con `\n` escapados. **No guardar el archivo JSON entero como valor de PRIVATE_KEY**. No se registran ni devuelven al navegador credenciales ni respuestas de error sensibles de Google.
6. Volver a desplegar en Coolify, iniciar sesión como administrador, abrir `/marketplace/seo/auditoria` y revisar la sección **Google Search Console · Inspección real**.
7. Introducir el **número de un anuncio público**, o usar **Preparar inspección en Google** desde un ejemplo de la auditoría, y pulsar **Inspeccionar en Google**. Ninguna consulta se dispara al cargar la página.

Para desactivar la conexión, establecer `GSC_READONLY_ENABLED=false` (y desplegar). No es necesario eliminar las variables para apagar el acceso desde la interfaz, aunque conviene revocar claves que dejen de usarse.

## Seguridad

- El endpoint `POST /api/admin/marketplace/seo/gsc/inspeccionar` exige `requireAdmin`, `Origin: https://redlibertad.com` y `Content-Type: application/json`, además de limitar a **6 solicitudes/hora por administrador dentro del proceso**.
- Solo admite `{ "id": "123" }` como identificador decimal de anuncio. Rechaza URLs elegidas por el cliente, números no válidos y cualquier parámetro arbitrario.
- La URL consultada se construye en el servidor mediante la misma ruta canónica del Marketplace, **solo si la ficha existe y está públicamente disponible**.
- La consulta SQL exige **todos** estos filtros: `l.status='active'`, `l.moderation_status='published'`, `u.status='active'`, `u.discoverable=true`.
- El servicio llama exclusivamente a las **dos direcciones HTTPS oficiales** de Google indicadas y no admite otros orígenes ni redirecciones HTTP. Dispone de tiempo límite y envía únicamente códigos de error controlados.
- Sin nuevas tablas, caches persistentes, tareas automáticas, ficheros de secretos ni almacenamiento de resultados. Respuestas privadas `Cache-Control: private,no-store`, `X-Robots-Tag: noindex,nofollow`.
- Los datos suministrados por Google aparecen únicamente como **texto**, no como enlaces ejecutables ni `innerHTML`.
- La petición de indexación o el uso del API Google Indexing **no está implementado**.

## Interpretación de resultados

El API devuelve `indexStatusResult` con `verdict`, `coverageState`, `indexingState`, `robotsTxtState`, `pageFetchState`, `lastCrawlTime`, `googleCanonical`, `userCanonical` y, si hay, una lista parcial de sitemaps conocidos por Google.

Se presentan esos campos explícitamente. **No** se inventan estadísticas globales, porcentajes de indexación, fechas de rastreo ausentes ni posiciones de búsqueda. Google podría seleccionar una URL canónica diferente, tener información desactualizada o devolver un veredicto de exclusión; esos resultados no activan cambios automáticos en las fichas.

Google impone límites a URL Inspection (entre otros, **2.000 consultas diarias por propiedad**, según documentación oficial en octubre de 2026). RedLibertad aplica un límite interno muy inferior y no inspecciona lotes en segundo plano.

## Pruebas / despliegue

- `npm run test:marketplace-gsc-readonly` usa claves de prueba generadas en memoria y respuestas Google simuladas. **No contacta Google ni usa secretos reales**.
- Valida autenticación de lectura, firma RS256, propiedad fijada a RedLibertad, rechazo de URLs externas, CSRF y métodos no JSON, límites de uso, respuesta desinfectada, y que el navegador no inspecciona nada sin pulsar el botón.
- PostgreSQL 18 comprueba de verdad que anuncios ocultos, pausados o pertenecientes a vendedores privados no pueden consultarse.
- Las suites anteriores de Marketplace/Stripe TEST deben seguir pasando. Solo fusionar si **todas** las comprobaciones están en verde y la rama no está retrasada.
- Primero fusionar, después desplegar en Coolify. **Sin credenciales, el panel debe permanecer desactivado.**
