# RedLibertad V3.2.102 — Nueva contratación tras cancelación Stripe TEST

**Base estable:** V3.2.101, SHA `14f4e045ee491dbab5adbd358242e6d604df1565`.

## Función de laboratorio
- Si la última suscripción TEST del administrador está **cancelada definitivamente** (`stripe_status='canceled'`), se habilita iniciar un **nuevo Checkout TEST**, incluyendo Profesional Plus.
- Un plan `active`, `trialing`, `past_due` o con cancelación únicamente programada continúa bloqueando un nuevo Checkout; no se interpreta como cancelado.
- Se exige que la identidad de la suscripción anterior esté vinculada a su Checkout TEST completado. Una fila antigua sin esta prueba queda bloqueada, en lugar de autorizar un cambio inseguro.
- Si existe un intento de Checkout aún pendiente de completar y creado durante las 24 h previas, se rechaza un nuevo intento para evitar sesiones de pago TEST superpuestas.
- Antes de generar otro Checkout, la suscripción cancelada queda copiada, de manera idempotente, en la nueva tabla **aislada** `marketplace_stripe_test_subscription_history`. Se conservan los Checkout anteriores y los eventos firmados recibidos.
- El estado actual puede cambiar a la nueva identidad únicamente por un evento de suscripción TEST vinculado a un Checkout nuevo, completado, del mismo vendedor y plan. El Checkout nuevo debe haberse creado después del Checkout de la suscripción cancelada.
- Los webhooks antiguos de una suscripción cancelada no pueden resucitarla. Si llega tarde un evento de una identidad anterior, no puede desplazar la suscripción TEST más reciente.
- En el panel privado, el botón de Checkout vuelve a habilitarse únicamente cuando el estado es `canceled`. El usuario puede consultar un breve listado de simulaciones archivadas. El texto diferencia explícitamente una cancelación definitiva de una programada.

## Pruebas
`npm run test:marketplace-stripe-reenrollment` verifica el alta TEST posterior a cancelación, tarifas exclusivamente desde servidor, suspensión de estados activos, bloqueo de historiales no verificados, Checkout pendiente, archivo inmutable, eventos antiguos y separación de cobros reales. Se mantienen todas las baterías GitHub Actions anteriores.

## Despliegue y datos
No se alteran tablas comerciales, WooCommerce, fotografías, productos, ni la suscripción gratuita piloto de MundoTaza. El único DDL nuevo crea la tabla e índice de historial de **pruebas** mediante `ensureSchema`; no destruye los registros anteriores. No hay variables nuevas. Antes de iniciar una nueva simulación, verificar que Coolify ejecuta el último SHA de `main`.

## Validación manual
1. Entrar como admin en `/marketplace/suscripciones/laboratorio`. Tras sincronizar, la anterior suscripción Profesional debe seguir en `canceled`.
2. Seleccionar Profesional Plus y abrir **Nueva simulación Stripe TEST**. Usar solo tarjeta test en el portal seguro de Stripe TEST.
3. Confirmar `checkout.session.completed` y `customer.subscription.created` en la lista de eventos. Ver estado de Plus activo; comprobar que Profesional figura en simulaciones anteriores.
4. Cancelar Plus inmediatamente desde Stripe TEST, sincronizar y confirmar `customer.subscription.deleted` y estado `canceled`.
5. Verificar en el Marketplace que los productos se pagan solo en la web del vendedor y que MundoTaza conserva todos sus datos y piloto gratuito.

**Límites permanentes:** Stripe LIVE, suscripciones comerciales, precios definitivos, contratos públicos, facturación real y concesión de derechos permanecen desactivados. Las facturas de Stripe TEST son simulaciones y no pagos reales.
