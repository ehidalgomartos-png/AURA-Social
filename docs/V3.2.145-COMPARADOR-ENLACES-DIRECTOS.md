# RedLibertad V3.2.145 — Enlaces reales al vendedor cuando la fuente los ofrece

## Objetivo
En la comparación del iPhone 12 de 128 GB, Pixmania muestra un precio de 259 € pero el visitante termina en una búsqueda general de Google. No debemos suponer una URL de producto de la tienda si no se ha obtenido una dirección fiable.

## Cambios
1. **Aprovechar los resultados ya descargados.** En la respuesta de Google Shopping, si el proveedor trae `link` o `direct_link` que apunta a un comercio por HTTPS, RedLibertad enlaza al producto de la tienda sin consumir ninguna búsqueda adicional.
2. **Resolver redirecciones reconocidas sin visitarlas.** Si SerpApi devuelve una URL `https://www.google.com/url?q=https%3A%2F%2Ftienda...`, se extrae únicamente la dirección HTTPS externa que contiene. No se siguen redirecciones, no se consideran vínculos de anuncios `/aclk`, ni se aceptan credenciales incrustadas, HTTP, direcciones locales o URLs que siguen siendo Google.
3. **Oferta exacta al consultar vendedor.** Google Shopping puede enviar el campo `immersive_product_page_token`. Lo conservamos dentro del JSON de la oferta y, cuando el usuario pulsa voluntariamente «Consultar enlace de la tienda», se usa para consultar **esa variante concreta** de la Google Product API en lugar de un `product_id` que puede agrupar distintas variantes.
4. **Una sola consulta autorizada** en el flujo voluntario: si el token existe y tiene formato válido se usa `page_token`; si no, el identificador anterior `product_id`. Nunca se prueba una segunda consulta de respaldo automáticamente.
5. **Comprobación del vendedor y el precio**: se mantiene la búsqueda de una tienda con nombre coincidente, precio en euros y tolerancia máxima existente (3 % o 3 €). Se puede utilizar `online_sellers[].link` cuando el proveedor no facilita `direct_link`, solo si contiene un destino HTTPS externo reconocible.
6. **Caché y experiencia**: si se ha obtenido y guardado un vínculo real previamente, aparece «Ver oferta en tienda». Las ofertas históricas sin ningún enlace directo mantienen «Buscar en Google». No se borra ni reescribe el inventario antiguo.

## Seguridad y SEO
- No se inventan enlaces de Pixmania, Wallapop u otras tiendas: únicamente se muestran URLs reales recibidas de SerpApi o verificadas con la consulta autorizada.
- Las consultas voluntarias se mantienen con POST + CSRF, limitador por IP y cuota compartida de SerpApi (12 al día / 220 al mes, salvo restricciones explícitas más bajas configuradas).
- En ningún caso se incluye la API key en HTML o el navegador. La página no hace peticiones directas desde el cliente a SerpApi.
- Publicidad patrocinada mantiene su etiqueta. Se mantienen los límites de indexación y el marcado SEO de comparaciones útiles; ninguna comparación es indexada solo por tener un enlace externo.
- No se modifican tablas PostgreSQL ni variables Coolify, y los nuevos campos JSON son opcionales (compatibilidad con registros existentes).

## Por qué este método
Los resultados orgánicos de Google Shopping suelen ofrecer `product_link` y `product_id`, que apuntan a Google, no necesariamente a la tienda. Los anuncios inline pueden ofrecer `link` directo. Google Product expone `sellers_results.online_sellers[].direct_link`, y las páginas identificadas por `page_token` corresponden a una oferta o variante concreta. Fuentes:
- https://serpapi.com/shopping-results
- https://serpapi.com/inline-shopping-results
- https://serpapi.com/google-product-api
