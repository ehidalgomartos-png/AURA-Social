# RedLibertad V3.2.94 — Protección ante webhooks Stripe TEST fuera de orden

Base estable `main`: V3.2.93, commit `99a6a800d841939fcafc4c175aa08e65795db9e4`.

## Cambio técnico concreto
- **Checkout TEST:** un webhook `checkout.session.expired` recibido después de `checkout.session.completed` ya no puede degradar el estado `completed` de una sesión que se completó. El evento tardío se registra como no aplicado. Un `completed` tardío sí puede prevalecer sobre `expired`, por seguridad ante desorden de entrega.
- **Suscripción TEST:** el upsert para un mismo vendedor exige que los IDs Stripe `subscription_id` y `customer_id` coincidan con los que ya estaban vinculados. Otro par distinto no reemplaza silenciosamente la suscripción anterior, aunque llegue con marca temporal superior; se registra como no aplicado para investigación posterior.
- Se conserva la regla anterior de solo aplicar eventos con fecha `created` estrictamente posterior. Los eventos duplicados siguen siendo idempotentes.
- No hay alteraciones de tablas ni rutas de Checkout; los guardarraíles afectan únicamente a las tablas `marketplace_stripe_test_*`.

## Límites
- Este cambio NO activa cobros reales ni es una solución completa para la transición entre suscripciones reales, la facturación fiscal, los registros contractuales o los eventuales casos de cambio de cuenta Stripe. Cuando se implemente Stripe LIVE será necesaria una reconciliación explícita y revisada de identidad.
- Las simulaciones administrativas, los precios comerciales privados y la prueba de Stripe TEST existente siguen disponibles.
- MundoTaza conserva su piloto gratuito, sincronización WooCommerce, medios, productos y compra externa. Los vendedores no están sujetos a nuevas cuotas ni restricciones.
