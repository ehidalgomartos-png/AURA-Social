# RedLibertad V3.2.49.1 — Editorial Encoding Hotfix

**Causa raíz:** el descargador del Centro Editorial convertía incondicionalmente los bytes de respuesta con `Buffer.toString('utf8')`. Los medios con Windows-1252 / ISO-8859-1 perdían ñ y acentos, mostrando caracteres de sustitución.

**Corrección:** decodificar del buffer original respetando BOM, `Content-Type: charset=...` y los `meta charset` o `http-equiv` tempranos. Usar UTF-8 estricto si no hay un charset conocido y fallback Windows-1252 si los bytes no son UTF-8 válidos. Ampliar las entidades HTML habituales del español (incluidas mayúsculas).

**Ámbito:** el mismo descargador se usa tanto en «Analizar noticia» como al guardar. No se altera la publicación automática (que permanece desactivada), la revisión, la fuente, las claves de API ni los registros existentes. Si un medio ya sirve caracteres de sustitución en origen, no pueden reconstruirse.

**Verificación:** `npm run test:editorial-encoding`, regresiones GitHub Actions y prueba manual con la URL de El Mundo mostrada en la incidencia.
