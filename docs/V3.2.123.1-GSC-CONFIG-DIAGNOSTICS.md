# RedLibertad V3.2.123.1 — Diagnóstico seguro de Google Search Console

## Incidencia en producción

Tras desplegar V3.2.123 y configurar las variables en Coolify, el panel devolvía el mensaje genérico «Completa la cuenta de servicio y la propiedad verificada en Coolify» y mantenía el botón de inspección desactivado. La V3.2.123 solo evaluaba `GSC_READONLY_ENABLED`, `GSC_SITE_URL`, `GSC_SERVICE_ACCOUNT_EMAIL` y si `GSC_SERVICE_ACCOUNT_PRIVATE_KEY` empezaba y terminaba con los marcadores PEM. No indicaba **cuál** era el campo incorrecto ni si el contenido de la clave podía leerse realmente como RSA.

Hubo exposición parcial de una clave de servicio durante el intento de configurarla. La clave expuesta debe estar **revocada** en Google Cloud, y únicamente debe quedar la clave nueva, almacenada como secreto de Coolify. Nunca solicitar, imprimir ni compartir credenciales o pantallas de sus valores.

## Corrección

### Diagnóstico privado del servidor, sin credenciales

El panel de administración `/marketplace/seo/auditoria`, desde el API ya protegido `GET /api/admin/marketplace/seo/auditoria`, incorpora seis comprobaciones independientes de solo lectura:

1. Integración activada: `GSC_READONLY_ENABLED` debe valer `true`.
2. Propiedad exacta: `sc-domain:redlibertad.com` o `https://redlibertad.com/`.
3. Correo válido de cuenta de servicio Google Cloud.
4. Clave privada presente.
5. Marcadores `BEGIN PRIVATE KEY` / `END PRIVATE KEY` completos.
6. Contenido PEM legible como clave privada **RSA** por el módulo `node:crypto`.

Cada una se muestra como aprobada o pendiente, con un texto fijo de ayuda. No se expone el correo, ID de clave, contenido, longitud, principio/final de la clave, huella, error interno de OpenSSL ni datos adicionales de Google.

El estado «Configurada» se muestra **solo si todas las comprobaciones locales pasan**. Eso **no garantiza** que Google haya concedido acceso: los permisos remotos se verifican al realizar la primera inspección manual.

### Compatibilidad del campo privado de Coolify

La normalización admite:

- PEM copiado con saltos de línea reales;
- valor JSON con secuencias literales `\n`;
- valor con los saltos doblemente escapados por un editor de variables;
- PEM envuelto opcionalmente en comillas simples o dobles;
- saltos de línea Windows `\r\n`.

Se preservan los requisitos de inicio y cierre PEM. No se acepta `private_key_id`, cadenas truncadas, contenido JSON sin extraer, claves de otro tipo o PEM malformado. No se intenta reconstruir automáticamente material criptográfico incompleto. Se limita el tamaño de entrada a 64 KiB.

**Importante**: si el usuario utiliza el editor masivo de Coolify, es preferible guardar `GSC_SERVICE_ACCOUNT_PRIVATE_KEY` como una sola variable de ejecución, usando los `\n` del valor `private_key` del JSON. No confundir el campo con `private_key_id` ni con el archivo completo.

### Sin peticiones automáticas

No se invoca a Google al consultar el diagnóstico. La inspección real sigue requiriendo `requireAdmin`, validación de origen, JSON, límites de frecuencia y acción manual. El alcance continúa siendo el permiso **`webmasters.readonly`**. Ningún producto, foto, inventario, sitemap, pago o parámetro de WooCommerce se modifica.

## Validación

`npm run test:marketplace-gsc-readonly` incorpora pruebas de formatos PEM, fallos separados por variable, RSA inválido o truncado, ausencia de filtraciones a la respuesta y renderizado seguro en móviles, utilizando claves RSA/EC de prueba generadas localmente durante las pruebas, **sin contactar con Google**.

No se introducen variables nuevas, rutas públicas ni tablas PostgreSQL. La batería general de GitHub Actions y las pruebas PostgreSQL 18 deben concluir en verde antes de fusionar.

## Después de desplegar

1. Desplegar V3.2.123.1 en Coolify y recargar la auditoría.
2. En «Google Search Console · Inspección real», comprobar la lista de aprobados/pendientes.
3. Si aparece una comprobación fallida, corregir **solo ese campo** en Coolify, sin revelar sus valores en capturas ni chats.
4. Repetir despliegue únicamente tras cambiar la variable necesaria.
5. Cuando todo aparezca aprobado, inspeccionar manualmente un anuncio público. Un error de autorización de Google se aborda entonces de forma distinta del formato de configuración.

No es preciso volver a generar ni sustituir la clave si la actual no ha sido expuesta ni revocada.
