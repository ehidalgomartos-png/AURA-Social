# RedLibertad V3.2.136 — Enlaces a vendedores bajo demanda

## Motivación
La captura real del 25/10/2026 muestra 18 ofertas de iPhone 13, casi todas con botón «Buscar en Google Shopping». El panel de SerpApi confirma que las consultas `engine=google_shopping` se ejecutan, pero el resultado principal generalmente proporciona `product_link` y no la dirección de compra.

## Solución
- Conserva el `shopping_results[].product_id` en las ofertas que se guardan en PostgreSQL **a partir de esta versión**.
- En ofertas con identificador, el usuario puede pulsar **Consultar enlace de la tienda**. **Solo este clic**, mediante POST protegido con CSRF, autoriza una consulta adicional de **Google Product API** (`engine=google_product`) por el producto elegido. No se hacen 18 consultas automáticamente.
- Consulta `sellers_results.online_sellers`, utiliza exclusivamente `direct_link` HTTPS y compara el nombre del vendedor con `source`; verifica que `base_price` en EUR coincida razonablemente (±3 % o 3 €) con el precio mostrado. En caso de duda, no redirige a una ficha de producto posiblemente equivocada.
- Si el enlace es válido, redirige al comercio con HTTP 303. Si no se puede verificar, comunica el resultado y conserva el enlace de búsqueda en Google Shopping como alternativa.
- Guarda cada comprobación (positiva o negativa) por oferta en PostgreSQL durante 24 horas. Bloquea llamadas simultáneas por la misma oferta, y cuando el enlace está verificado lo muestra directamente en la tarjeta.
- Comparte el presupuesto de créditos **existente** de SerpApi (`COMPARADOR_DAILY_LIMIT=5`, `COMPARADOR_MONTHLY_LIMIT=100` por defecto) mediante la reserva transaccional ya implantada. No permite consultas extras si el presupuesto está agotado.
- El filtro por modelo, las condiciones (nuevo/reacondicionado), el SEO editorial, la actualización en segundo plano y las URLs permanentes continúan.

## Limitaciones
- Cada primera pulsación de «Consultar enlace de la tienda» de una oferta no verificada puede consumir **una búsqueda adicional** del plan de SerpApi. Consultar ofertas guardadas o visitar una tienda con URL ya verificada no genera ese coste.
- Google Product API puede no encontrar una oferta del vendedor al precio que mostraba Google Shopping. En ese caso no afirmamos que exista un enlace directo.
- Las fichas **antiguas** sin `product_id` no pueden resolverse a partir del enlace de búsqueda que ya guardamos; necesitan una nueva consulta una vez caducada la caché de 24 horas.
- El enlace directo es el aportado por SerpApi; no verificamos que el producto esté en stock o que el precio final, impuestos y transporte coincidan al llegar al comercio.
- Esto no crea una cuenta Merchant Center ni usa scraping directo de Google.

## Seguridad
- Los identificadores se obtienen de ofertas guardadas en PostgreSQL, nunca de una URL escrita libremente por el usuario.
- Solicitud POST con token CSRF, 8 clics/hora/IP de límite adicional, bloqueo transaccional por oferta y cuota diaria/mensual compartida.
- API key solo en servidor; no se muestra al navegador.
- No se persisten nombres ni datos personales del visitante que pulsa.
