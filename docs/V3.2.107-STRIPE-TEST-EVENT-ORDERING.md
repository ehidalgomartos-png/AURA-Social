# RedLibertad V3.2.107 — Stripe TEST: orden estable de cancelaciones

**Base estable:** V3.2.106, `95a7f7f4e19a7060393fa0b305f40352d99f645d`.

## Problema detectado durante revisión técnica

Stripe asigna `event.created` con precisión de **segundos**. La lógica anterior guardaba `last_event_created` y únicamente admitía actualizaciones con una marca estrictamente posterior. Si la creación, actualización y **cancelación definitiva** de una suscripción de laboratorio llegaban con **la misma marca temporal**, la cancelación se ignoraba aunque su evento fuese válido y estuviera vinculado a un Checkout TEST verificado. El laboratorio podía mostrar una suscripción activa que ya estaba cancelada en Stripe TEST.

## Corrección

Solo para **la misma pareja de cliente y suscripción Stripe TEST**:
- Se sigue aceptando normalmente cualquier webhook autorizado con `event.created` **mayor** al último aplicado.
- A igualdad de `event.created`, solamente un evento autenticado de tipo `customer.subscription.deleted` con `stripe_status='canceled'` tiene precedencia sobre el estado **aún no cancelado**.
- Una actualización ordinaria con la misma marca temporal no puede modificar el estado.
- Una vez alcanzado `canceled`, ni eventos retrasados posteriores ni eventos repetidos pueden resucitar la suscripción.
- La transición a una **nueva identidad de suscripción** sigue exigiendo Checkout TEST nuevo, completado y verificado, posterior al checkout anterior. El historial permanece intacto.

No se confía en datos enviados por el navegador para identificar la cancelación. La entrada procede del webhook firmado de Stripe TEST, con validación previa del precio, vendedor, cliente y suscripción. Si eventos legítimos sin cancelación llegan en el mismo segundo pero en orden equivocado, la sincronización manual de Stripe TEST continúa disponible para restaurar su estado canónico sin reactivar ninguna suscripción comercial.

## Verificación automática

- `npm run test:marketplace-stripe-event-order`: verifica el tipo de evento como parámetro del SQL, la prioridad terminal, la idempotencia y el mantenimiento de todos los interruptores LIVE apagados.
- `tests/marketplace-stripe-reenrollment-postgres-v32102.test.js`: prueba funcional sobre **PostgreSQL 18 temporal**, sin Stripe ni producción, con una actualización normal y una cancelación creadas en el **mismo segundo**. Comprueba que no se aplica la actualización normal, sí se aplica la cancelación y se rechazan las resurrecciones posteriores.
- Se mantienen todas las regresiones existentes de seguridad, suscripciones, Marketplace y WooCommerce.

## Alcance y decisiones reservadas

- Solo las tablas `marketplace_stripe_test_*` pueden recibir efectos de la corrección. No hay nueva estructura de DB, variables, credenciales, formularios ni datos personales.
- **Stripe LIVE, cobros reales, planes públicos, facturación, impuestos, consentimiento y permisos comerciales permanecen desactivados.** Se respeta expresamente que la elección de sistema de facturación queda aparcada.
- MundoTaza sigue con piloto gratuito; compras de productos en las webs externas de vendedores, con WooCommerce, fotos y medios preservados.
- La V3.2.107 no autoriza el lanzamiento. El resto de decisiones legales y comerciales quedan pendientes de revisión independiente.
